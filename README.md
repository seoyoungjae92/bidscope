# 입찰레이더 (bidscope)

공공입찰 공고를 **뜨기 전에** 알려주는 토스 앱인토스 미니앱.
2026-09-22 출시, 1인 개발·운영 중.

---

## 무엇을, 왜

나라장터 입찰은 공고가 뜨면 마감까지 보통 2주 남짓이다. 그런데 공고 전에
**사전규격**(의견 수렴) 단계가 먼저 공개된다. 직접 API로 대조해 보니
같은 사업 기준 **중앙값 7일** 먼저 떴다(표본 26건, [VERIFIED.md](VERIFIED.md)).

**일주일을 더 버는 것** — 이게 이 제품의 전부다. 화면도, 이름도, 푸시 순서도 전부 이것을 가리킨다.

```
사전규격 공개 ──(중앙값 7일)──> 입찰공고 ──(2주)──> 마감
    ↑                              ↑                  ↑
 "공고 예고" 알림              "새 공고" 알림      "마감 임박" 알림
```

사용자는 분야(대분류→중분류)·사업 규모·계약 방법으로 조건을 등록하고,
맞는 공고만 하루 한 번 묶어서 푸시로 받는다.

## 구성

```
server/     수집·매칭·푸시·API + 스케줄러   Python 3.12, 의존성 0
miniapp/    토스 미니앱                     Vite + React 19 + @apps-in-toss 3.4.1
```

```
 조달청 나라장터 OpenAPI 2종
   입찰공고정보서비스(15129394) · 사전규격정보서비스(15129437)
          │ 09 / 13 / 18시 KST 증분 수집
          ▼
 ┌──────────────────────────────────────┐
 │ Railway 컨테이너 (단일 프로세스)        │
 │   api.py        stdlib HTTP 서버       │
 │    ├ scheduler  데몬 스레드 (배치)      │
 │    └ SQLite     Railway 볼륨 /data     │
 └──────────────────────────────────────┘
      │ HTTPS                  │ mTLS
      ▼                        ▼
 토스 미니앱 (WebView)     토스 스마트메시지
 익명키로 사용자 식별       템플릿 3종
```

미니앱은 `.ait` 번들을 토스 콘솔에 올리면 토스가 호스팅한다 — 별도 프런트 배포처가 없다.

## 기술 선택과 이유

| 선택 | 이유 |
|---|---|
| **의존성 0** (표준 라이브러리만) | 하루 수백 요청 규모에 프레임워크가 필요 없다. 의존성이 없으면 보안 패치 추적·빌드 실패 지점이 사라진다. `requirements.txt`는 주석만 있는 빈 파일이다 |
| **SQLite** | 단일 인스턴스라 쓰기 경합이 없고 백업이 파일 복사다. 사용자가 늘면 Postgres로 옮긴다 |
| **스케줄러를 API와 같은 프로세스에** | Railway 볼륨은 서비스당 1개라, 배치를 별도 서비스로 빼면 같은 SQLite를 못 본다. 대신 재시작으로 슬롯을 건너뛸 수 있어 **부팅 시 따라잡기**를 넣었다 |
| **로그인 없음** | 토스 익명키(`getAnonymousKey`)만으로 기기 단위 식별이 된다. 개인정보를 받지 않고, 로그인 동의 화면에서의 이탈도 없다 |
| **푸시는 다이제스트 1통** | 건별로 보내면 곧 알림을 끈다. 하루 한 번, 본문에는 상위 20건까지 |

## 데이터 흐름

1. **수집** — `work_type`별 커서(마지막 조회 시각) 이후만 조회한다. 전체 스캔도, 중복 제거도 필요 없다.
   원본 응답을 `raw` 컬럼에 함께 저장해 스키마 변경에 대비한다.
2. **매칭** — SQL 한 번으로 조건 × 공고를 조인해 알림 큐에 넣는다.
   선택 항목은 `조건이 비어 있으면 통과`로 처리해 동적 쿼리 조립을 없앴다.
   ```sql
   and (c.lrg_clsfc is null or n.lrg_clsfc = c.lrg_clsfc)
   and (c.amt_min   = 0    or n.presmpt_prce >= c.amt_min)
   ```
3. **백필** — 조건을 새로 등록하면 기존 공고를 즉시 채운다.
   없으면 등록 직후 빈 화면을 본다. 단 발송 완료로 표시해 **푸시는 내보내지 않는다**
   (등록하자마자 수십 건이 쏟아지면 그대로 알림을 끈다).
4. **발송** — 09:10 신규·예고, 15:00 마감 임박(6~48시간 내 마감 + 이미 신규 알림을 보낸 건만).

## 설계 결정

실측에서 나온 것만 적는다. 근거는 [VERIFIED.md](VERIFIED.md)에 있다.

- **MVP는 용역만.** 업무유형 4종 중 분류체계가 채워져 오는 유일한 유형이다.
  물품은 표본 300건 전부 분류가 비어 있었다.
- **분류 2단계 선택이 주 매칭축.** 계약방법만 걸면 일 180건, 분류를 걸면 일 13건이다.
- **사전규격은 키워드로만 매칭.** 사전규격 데이터에는 분류 필드가 없다.
  분류명 토큰 매칭도 시도했으나 "사업"이 696건 중 186건을 잡아 폐기했다.
- **마감일시가 없는 14%는 버리지 않는다.** 놓치는 쪽이 더 나쁘다.
- **조건 3개 제한은 과금 장치가 아니라 어뷰징 방어선.**

## 겪은 문제 몇 가지

전체 목록은 [HANDOFF.md](HANDOFF.md)의 "겪어본 함정들"에 있다.

- **마감된 공고가 계속 노출됐다.** 컨테이너가 UTC인데 `TZ=Asia/Seoul`이 안 먹었다 —
  이미지에 tzdata가 없어서였다. SQL에 `datetime('now','+9 hours')`를 직접 박아 해결했다.
- **푸시가 사흘간 한 통도 안 나갔다.** 함수 이름을 바꾸고 호출부(`scheduler.py`)를 안 고쳤는데
  파이썬이라 런타임까지 드러나지 않았다. 고친 뒤 **스케줄러가 참조하는 이름이 실제로 존재하는지
  AST로 검사하는 테스트**를 추가했다.
- **심사 반려: 최초 접속 20초 초과.** 익명키 요청과 `fetch` 양쪽에 타임아웃이 없어
  첫 화면이 무한정 멈출 수 있었다. 각각 3초·5초 상한을 두고 실패 시 재시도 버튼을 뒀다.
- **익명키 실패 시 모든 사용자가 같은 키를 썼다.** 개발용 고정 폴백이 운영 번들에 남아
  해당 사용자들끼리 조건이 섞일 수 있었다. 기기별 임의 키로 바꿨다.

## 빠른 시작

```bash
# 서버 (배포본을 쓰면 띄우지 않아도 된다)
cd server
export G2B_KEY='data.go.kr 디코딩 인증키'
python3 g2b.py run        # 수집 + 매칭
ALLOW_ORIGINS=http://localhost:5180 python3 api.py

# 미니앱
cd miniapp && cp .env.example .env && npm install && npm run dev -- --port 5180
```

`.env` 기본값이 배포 서버를 가리킨다. 로컬 서버를 보려면 `VITE_API_BASE`를 바꾼다.

### 테스트

```bash
cd server  && python3 test_match.py && python3 test_api.py
cd miniapp && npm test
```

### 빌드·배포

```bash
cd miniapp
npm version <다음 버전> --no-git-tag-version   # 같은 버전은 콘솔이 거부한다
npm run build                                 # → bidscope.ait, 콘솔에 업로드
```

서버는 main에 push하면 Railway가 자동 배포한다(헬스체크 통과 후 전환).
